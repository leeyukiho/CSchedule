# 新增学校接入流程

本文是给 AI Agent 和开发者执行的学校扩展规程。目标是让新增学校时能准确判断学校类型、识别是否夹了一层认证或前端壳、落到正确文件、返回正确缓存结构，并避免把学校差异写进通用前端或后端业务代码。

## 0. 开始前必须先判型

在修改任何文件前，先输出一段“学校接入判型”，内容必须包括：

```text
学校：<学校全称>
是否为全新学校：是/否
拟复用 provider：<providerId 或 none>
登录层：direct_password / CAS / WebVPN / OAuth / WebView / unknown
数据层：EAMS / 正方 jwglxt / 强智 / URP / JSON API / unknown
是否夹杂一层：否 / 是，夹层是 <WebVPN/CAS/门户页/前端 SPA/token 签名/API 网关/其他>
推荐接入模式：cloud_worker / webview_client_fetch / manual_import / researching
本次允许标为 enabled：是/否
```

如果是全新学校，AI 必须先用 Firecrawl 调研学校官网、教务系统入口、登录页、跳转链路和公开可见页面结构，再写 provider 或云函数。没有 Firecrawl 调研证据时，只能把状态写成 `researching` 或 `candidate`，不能直接写 `enabled`。

如果发现学校不是直连教务系统，而是多了一层 WebVPN、CAS、统一身份认证、门户中转、前端 SPA、token 签名或 API 网关，必须在判型里明确指出“夹杂一层”。这种学校不能按普通 HTML 教务系统照抄，必须把夹层登录、跳转、token、签名或入口发现逻辑放进学校专用云函数或 WebView 流程。

## 1. 当前已有学校类型

| providerId | 学校 | 登录层 | 数据层 | 是否夹杂一层 | 处理方式 |
| --- | --- | --- | --- | --- | --- |
| `wtbu` | 武汉工商学院 | 账号密码直登 | EAMS HTML | 否 | 可参考普通 EAMS + `cloud_worker` |
| `whhxit` | 武汉华夏理工学院 | 账号密码直登 | 正方 jwglxt | 否 | 可参考正方 V9 + `cloud_worker` |
| `wdu` | 武汉东湖学院 | 账号密码直登 | 正方 jwglxt | 否 | 可参考正方 V9 + `cloud_worker` |
| `bwu` | 北京物资学院 | WebVPN/CAS | EAMS | 是，WebVPN/CAS 包住 EAMS | 必须先处理 WebVPN/CAS，再进 EAMS |

判断复用时只复用“数据层解析模式”，不要忽略登录层。比如 EAMS 不等于一定能复用 `wtbu`；如果前面有 WebVPN/CAS，它更接近 `bwu`。

## 2. 文件边界

通常只允许改这些文件：

```text
backend/src/modules/providers/adapters/<providerId>.provider.ts
backend/src/modules/providers/providers.module.ts
backend/prisma/data/connected-schools.json
cloudfunctions/sync<School>/index.js
cloudfunctions/sync<School>/package.json
cloudbaserc.json
docs/cloudbase-functions.md
docs/providers/<学校或providerId>.md
```

不要为了新增学校修改小程序页面、通用同步服务、通用缓存写入服务或 Prisma 表结构，除非需求明确改变了平台能力边界。若确实要改函数、类或方法，必须先按 `AGENTS.md` 使用 GitNexus `impact` 做影响分析；高风险结果要先告知用户。

## 3. 正确数据流

新增学校必须落到这条链路：

```text
School / connected-schools.json
  -> SchoolProvider 元数据
  -> 学校专用云函数或 WebView 上传
  -> 标准 cacheResults
  -> 后端写 CourseCache / FeatureCache
  -> 前端按 display schema 展示
```

普通读取接口只读缓存，不访问学校系统。后端 provider adapter 只写元数据和展示配置，不写学校登录、HTTP 请求、HTML 解析、Cookie、Token 或签名算法。

## 4. 新增学校执行顺序

1. 用 Firecrawl 调研新学校，或读取已有 `docs/providers/*.md` 作为证据。
2. 输出“学校接入判型”，尤其说明是否夹杂一层。
3. 决定 `providerId`、`loginMode`、`eduSystemType`、`dataAccess` 和 `status`。
4. 新增或修改 `backend/src/modules/providers/adapters/<providerId>.provider.ts`。
5. 在 `backend/src/modules/providers/providers.module.ts` 注册 provider。
6. 在 `backend/prisma/data/connected-schools.json` 新增学校配置。
7. 如果声明 `cloud_worker`，实现并部署 `cloudfunctions/sync<School>`。
8. 更新 `cloudbaserc.json` 和 `docs/cloudbase-functions.md`。
9. 用真实授权账号验收绑定、同步和页面展示。
10. 只有验收通过后，才把 `status` 改为 `enabled`。

## 5. providerId 和命名

- `providerId` 使用小写字母数字或短横线，例如 `wtbu`、`whhxit`。
- provider 文件为 `backend/src/modules/providers/adapters/<providerId>.provider.ts`。
- provider 导出变量为 `<providerId>Provider`，例如 `wtbuProvider`。
- 云函数目录为 `cloudfunctions/sync<School>`，例如 `syncWtbu`。
- `connected-schools.json` 里的 `id` 默认等于 `providerId`。只有一套 provider 明确服务多所学校时，才允许不同。

## 6. SchoolProvider 只写元数据

最小结构：

```ts
import { SchoolProvider } from '../provider.types'

export const xxxProvider: SchoolProvider = {
  id: 'xxx',
  meta: {
    id: 'xxx',
    name: '学校全称',
    shortName: '学校简称',
    providerId: 'xxx',
    loginMode: 'direct_password',
    eduSystemType: 'eams',
    status: 'beta',
    verifiedAt: '2026-07-03T00:00:00.000Z',
    capabilities: { course: true, score: false, exam: false, profile: false },
    dataAccess: {
      course: ['cloud_worker'],
      score: [],
      exam: [],
      profile: [],
    },
    credentialSave: {
      passwordVaultAllowed: true,
      autoSync: 'password_login',
      scheduledSyncSupported: true,
      title: '支持保存登录信息',
      notice: '保存教务账号密码后，可通过云函数完成首次导入和后续自动同步。账号密码会加密保存在后端，不会用于后端直连学校系统。',
      consentLabel: '加密保存账号密码，用于自动同步',
    },
    featureDisplay: {
      course: {
        title: '课表',
        kind: 'course_grid',
        itemPath: 'courses',
        itemFields: [
          { key: 'name', label: '课程', primary: true },
          { key: 'teacher', label: '教师' },
          { key: 'classroom', label: '教室', fallbackKeys: ['location'] },
          { key: 'weeks', label: '周次' },
        ],
        emptyText: '暂无课表数据',
      },
    },
  },
}
```

硬性规则：

- `id`、`meta.id`、`meta.providerId` 必须一致。
- `capabilities.<target>` 只能对已经解析并验收的能力写 `true`。
- `dataAccess.<target>` 只能写实际可用的接入方式。
- 只有云函数已经实现并返回该 target 的 `cacheResults`，才能写 `cloud_worker`。
- provider adapter 不得包含学校登录、请求、解析、Cookie、Token、签名或数据库逻辑。

## 7. 注册 provider

修改：

```text
backend/src/modules/providers/providers.module.ts
```

加入 import：

```ts
import { xxxProvider } from './adapters/xxx.provider'
```

在 `useFactory` 中注册：

```ts
registry.register(xxxProvider)
```

## 8. connected-schools.json 层级

修改：

```text
backend/prisma/data/connected-schools.json
```

这里写的是 seed 文件字段 `providerConfig`。进入数据库后，seed 会把它放到 `School.config.provider`。因此：

- 在 `connected-schools.json` 写 `providerConfig`。
- 不要在 `connected-schools.json` 手动包一层 `config.provider`。
- 运行时服务会从 `config.provider.cloudFunctions` 等字段读取配置。

模板：

```json
{
  "id": "xxx",
  "catalogCode": "4142000000",
  "name": "学校全称",
  "shortName": "学校简称",
  "province": "湖北省",
  "city": "武汉市",
  "aliases": ["学校全称", "学校简称", "XXX", "xxx"],
  "providerId": "xxx",
  "loginMode": "direct_password",
  "eduSystemType": "eams",
  "homepageUrl": "https://jw.example.edu.cn",
  "authUrl": "https://jw.example.edu.cn/login",
  "verifiedAt": "2026-07-03T00:00:00.000Z",
  "status": "beta",
  "capabilities": {
    "course": true,
    "score": false,
    "exam": false,
    "profile": false
  },
  "dataAccess": {
    "course": ["cloud_worker"],
    "score": [],
    "exam": [],
    "profile": []
  },
  "providerConfig": {
    "baseUrl": "https://jw.example.edu.cn",
    "system": "EAMS",
    "cloudFunctions": {
      "course": {
        "functionName": "syncXxx",
        "url": "https://your-cloud-function-url.example.com/syncXxx"
      }
    },
    "authConfig": {
      "captchaRequired": false,
      "captchaKind": "none",
      "uiPreset": "password",
      "passwordTransform": "plain"
    },
    "sectionTimes": [
      { "section": 1, "start": "08:00", "end": "08:45" },
      { "section": 2, "start": "08:55", "end": "09:40" }
    ]
  }
}
```

字段一致性规则：

- `providerId` 必须指向已注册 provider。
- `loginMode` 必须来自 `LoginMode`：`direct_password`、`password_captcha`、`cas_simple`、`cas_webview`、`oauth_webview`、`qrcode`。
- `eduSystemType` 必须来自 `EduSystemType`：`eams`、`zf_jwglxt`、`qiangzhi`、`urp`、`cas`、`oauth`、`custom`、`unknown`。
- `dataAccess.<target>` 中出现 `cloud_worker` 时，必须有 `providerConfig.cloudFunctions.<target>.url`。
- 同一次同步请求的多个 target 必须使用同一个 `functionName` 和 `url`，否则后端不会合并调用。
- 有验证码、扫码、短信、滑块、人脸、设备校验或强 WebView 行为时，不要写普通 `direct_password + cloud_worker`。

## 9. 云函数职责

只有声明 `cloud_worker` 时才需要学校专用云函数：

```text
cloudfunctions/syncXxx/index.js
cloudfunctions/syncXxx/package.json
```

云函数负责：

- 校验 `x-cschedule-worker-secret` 或前端短期 `clientImportToken`。
- 处理该学校的登录层，包括直登、CAS、WebVPN、门户跳转、token 或签名。
- 按 `targets` 抓取学校数据。
- 解析为标准 `cacheResults`。
- 返回可读错误码，不泄露账号、密码、Cookie、Token、完整 HTML 或完整 JSON。

云函数不负责：

- 写数据库。
- 创建用户或绑定关系。
- 决定学校是否 enabled。
- 修改 provider 元数据。
- 输出敏感调试日志。

后端自动同步入参：

```json
{
  "source": "backend_auto_sync",
  "schoolId": "xxx",
  "providerId": "xxx",
  "targets": ["course"],
  "username": "学号",
  "password": "密码",
  "semesterId": "2025-2026-1"
}
```

成功返回：

```json
{
  "ok": true,
  "result": {
    "targets": ["course"],
    "cacheResults": [
      {
        "target": "course",
        "termId": "2025-2026-1",
        "cacheData": {
          "termId": "2025-2026-1",
          "courses": [],
          "terms": [],
          "sectionTimes": [],
          "meta": { "source": "cloud_worker" }
        },
        "parsedCount": 0,
        "sourceHash": "optional-source-hash",
        "syncedAt": "2026-07-03T00:00:00.000Z",
        "warnings": []
      }
    ]
  }
}
```

失败返回：

```json
{
  "ok": false,
  "errorCode": "LOGIN_FAILED",
  "errorMessage": "账号或密码错误"
}
```

推荐错误码：`SYNC_INPUT_INVALID`、`WORKER_SECRET_NOT_CONFIGURED`、`WORKER_UNAUTHORIZED`、`PROVIDER_NOT_FOUND`、`TARGET_UNSUPPORTED`、`LOGIN_FAILED`、`SCHOOL_SYSTEM_UNAVAILABLE`、`PARSE_FAILED`、`CLOUD_SYNC_EMPTY_RESULT`。

## 10. cacheData 结构

`target=course` 必须把课表放在 `cacheData.courses`：

```json
{
  "termId": "2025-2026-1",
  "courses": [
    {
      "id": "course-1",
      "name": "高等数学",
      "teacher": "张老师",
      "location": "1教101",
      "classroom": "1教101",
      "weekday": 1,
      "sections": [1, 2],
      "startSection": 1,
      "endSection": 2,
      "weeks": [1, 2, 3, 4, 5],
      "rawWeeks": "1-5周",
      "campus": "主校区",
      "remark": ""
    }
  ],
  "terms": [{ "id": "2025-2026-1", "name": "2025-2026学年第1学期" }],
  "sectionTimes": [{ "section": 1, "start": "08:00", "end": "08:45" }],
  "meta": { "source": "cloud_worker" }
}
```

`target=score`、`target=exam`、`target=profile` 放在 `cacheData.data`。不要把 profile 混进 score，也不要一次同步顺手覆盖未请求 target。

课表字段要求：

- `name` 必填。
- `weekday` 用 `1` 到 `7` 表示周一到周日。
- `weeks` 用数字数组，不要只返回中文周次字符串。
- `sections`、`startSection`、`endSection` 至少提供一种，推荐都提供。
- `location` 和 `classroom` 至少提供一个。

## 11. 状态规则

- `researching`：只有调研资料，没有可用解析。
- `candidate`：已有候选方案，但未完成真实账号验收。
- `beta`：至少一个 target 可用，但还需要小范围验证。
- `enabled`：真实账号完成绑定、同步、缓存写入、前端展示验收。
- `disabled`：不可用或下线。

新学校默认从 `researching` 或 `candidate` 开始。没有真实账号验收，不得写 `enabled`。

## 13. 上线前清单

```text
[ ] 已用 Firecrawl 或已有 provider 文档完成调研
[ ] 已输出学校接入判型
[ ] 已明确是否夹杂一层
[ ] providerId、meta.id、meta.providerId 一致
[ ] providers.module.ts 已注册 provider
[ ] connected-schools.json 是合法 JSON
[ ] connected-schools.json 使用 providerConfig，不手动写 config.provider
[ ] capabilities 与实际已验收 target 一致
[ ] 每个 cloud_worker target 都有 cloudFunctions.<target>.url
[ ] 多 target 使用同一个云函数 URL
[ ] 云函数不会记录敏感信息
[ ] backend 与云函数配置同一个 CSCHEDULE_WORKER_SECRET
[ ] 真实账号完成首次绑定
[ ] 真实账号完成手动同步
[ ] CourseCache 或 FeatureCache 确认写入
[ ] 前端页面按 display schema 正常展示
[ ] status 只在验收通过后写 enabled
```

## 14. 禁止事项

- 不要在 provider adapter 写登录、抓取、解析、Cookie、Token 或签名逻辑。
- 不要恢复后端直连学校系统的旧模式。
- 不要把未验收能力写成 `true`。
- 不要把未配置云函数 URL 的 target 写成 `cloud_worker`。
- 不要把 `CSCHEDULE_WORKER_SECRET` 放进前端或仓库。
- 不要手动改数据库来接入学校，除非是在处理明确的数据修复任务。
- 不要看到同一套教务系统名称就直接复用；先判断是否夹了 WebVPN、CAS、门户、SPA、token 或签名层。
